# C4 Working Prototype 데이터 설정 기준

이 문서는 2026-07-22 수요일까지 유저 테스트 가능한 Working Prototype을 만들기 위한 데이터 기준이다.

이번 단계의 목표는 완성형 앱을 만드는 것이 아니라, 유저 테스트에서 핵심 경험이 끊기지 않게 보여주는 것이다. 따라서 서버, 로그인, 친구 추가, 영구 저장, 복잡한 예외 처리는 이번 범위에서 제외하고 MockData와 하드코딩을 적극 사용한다.

## 1. 한 줄 요약

앱은 자매가 이미 연결된 상태로 시작한다. 옷, 자매, 대여 상태, 후기, 감사편지는 MockData 또는 하드코딩으로 준비하고, 포인트 차감과 빌린 상태 변화만 유저 테스트 중 실제로 바뀌게 만든다.

## 2. 이번 테스트에서 보여줄 핵심 플로우

```text
온보딩
→ 자매가 이미 추가된 상태로 본편 시작
→ 언니 옷장 보기
→ 옷 상세 보기
→ 빌려오기
→ 포인트 차감
→ 빌린 상태 확인
→ 반납
→ 사진 후기 / 감사편지 흐름 확인
```

이 플로우에 직접 필요하지 않은 기능은 만들지 않는다.

## 3. 이번 범위에서 제외하는 것

| 제외 항목 | 기준 |
| --- | --- |
| 실제 로그인 | 만들지 않는다. 현재 사용자는 고정값으로 둔다. |
| 자매 추가 / 친구 요청 | 만들지 않는다. 이미 자매가 연결된 상태로 시작한다. |
| 서버 연동 | 만들지 않는다. |
| JSON 파일 저장 | 필수 아님. 앱 실행 중 로컬 상태 변화만 확인한다. |
| 옷 업로드 요청 | 만들지 않는다. |
| 보관 / 삭제 / 탈퇴 | 만들지 않는다. |
| 복잡한 예외 처리 | 유저 테스트 흐름에 필요한 최소 처리만 한다. |

## 4. 데이터 구성

Working Prototype에서 필요한 데이터는 아래 정도로 제한한다.

```text
MockData
├─ currentUser
├─ sisters
├─ clothItems
├─ rentals
├─ thankYouLetters
└─ reviewSamples
```

| 데이터 | 역할 |
| --- | --- |
| `currentUser` | 앱을 사용하는 현재 사용자. 포인트 값을 가진다. |
| `sisters` | 이미 연결된 언니 목록. 최소 2명 준비한다. |
| `clothItems` | 언니 옷장에 보일 옷 데이터. asset 이름과 연결된다. |
| `rentals` | 빌린 옷 상태를 보여주기 위한 대여 상태 데이터. |
| `thankYouLetters` | 감사편지 화면에 보여줄 예시 데이터. |
| `reviewSamples` | 사진 후기 흐름에 보여줄 예시 데이터. |

## 5. 최소 모델 기준

실제 구현에서는 아래 필드를 그대로 맞출 필요는 없지만, 화면 간 데이터 기준은 이 정도로 통일한다.

### 5.1 CurrentUser

| 필드 | 설명 |
| --- | --- |
| `id` | 현재 사용자 식별값 |
| `name` | 사용자 이름 |
| `point` | 현재 포인트 |
| `profileImageName` | 프로필 이미지 asset 이름 |

기준:

- 현재 사용자는 고정값으로 둔다.
- 포인트는 빌려오기 시 실제로 차감되어 화면에 반영되어야 한다.

### 5.2 Sister

| 필드 | 설명 |
| --- | --- |
| `id` | 언니 식별값 |
| `name` | 언니 이름 |
| `profileImageName` | 프로필 이미지 asset 이름 |
| `relationshipLabel` | 첫째 언니, 둘째 언니 같은 표시용 문구 |

기준:

- 자매 추가 화면이나 요청 흐름은 만들지 않는다.
- 앱 시작 시 이미 언니들이 연결된 상태로 보여준다.

### 5.3 ClothItem

| 필드 | 설명 |
| --- | --- |
| `id` | 옷 식별값 |
| `ownerId` | 어떤 언니의 옷인지 |
| `name` | 옷 이름 |
| `category` | 상의, 하의, 아우터, 원피스 등 |
| `imageName` | 화면에서 사용할 asset 이름 |
| `pointCost` | 빌릴 때 차감할 포인트 |
| `isBorrowed` | 현재 빌린 상태인지 |
| `description` | 상세 화면용 짧은 설명 |

기준:

- `imageName`은 린이 업로드하는 asset 이름과 맞춘다.
- 화면 구현을 빠르게 하기 위해 enum보다 문자열을 써도 된다.
- 옷 상세에 필요한 설명은 하드코딩해도 된다.

### 5.4 Rental

| 필드 | 설명 |
| --- | --- |
| `id` | 대여 식별값 |
| `clothItemId` | 빌린 옷 |
| `borrowerId` | 현재 사용자 |
| `ownerId` | 옷 주인 |
| `status` | `borrowed`, `returned` 정도만 사용 |

기준:

- 빌려오기 버튼을 누르면 해당 옷이 빌린 상태로 바뀌어야 한다.
- 빌린 옷 상태는 별도 화면이나 카드에서 확인 가능해야 한다.
- 반납하면 사진 후기 / 감사편지 흐름으로 이어질 수 있어야 한다.

### 5.5 ReviewSample

| 필드 | 설명 |
| --- | --- |
| `id` | 후기 식별값 |
| `clothItemId` | 어떤 옷에 대한 후기인지 |
| `imageName` | 후기 이미지 asset 이름 |
| `message` | 후기 문구 |

기준:

- 실제 사진 저장은 이번 범위에서 필수 아님.
- 사진 후기는 유저 테스트에서 흐름이 보이도록 하드코딩된 예시를 사용해도 된다.

### 5.6 ThankYouLetter

| 필드 | 설명 |
| --- | --- |
| `id` | 편지 식별값 |
| `toSisterId` | 받을 언니 |
| `clothItemId` | 빌렸던 옷 |
| `message` | 감사편지 문구 |

기준:

- 실제 전송 기능은 만들지 않는다.
- 작성 또는 확인 흐름이 유저 테스트에서 이해되면 충분하다.

## 6. 화면별 데이터 기준

| 화면 | 사용하는 데이터 | 기준 |
| --- | --- | --- |
| 온보딩 | 고정 문구, currentUser | 온보딩 후 본편으로 이동한다. |
| 홈 | currentUser, sisters, rentals | 자매가 이미 연결된 상태를 보여준다. |
| 언니 옷장 | sisters, clothItems | 선택한 언니의 옷만 보여준다. |
| 옷 상세 | clothItems | 옷 이미지, 설명, 포인트 비용을 보여준다. |
| 빌려오기 | currentUser, clothItems, rentals | 포인트 차감과 빌린 상태 변경이 일어난다. |
| 빌린 옷 확인 | rentals, clothItems | 내가 빌린 옷 상태를 보여준다. |
| 반납 | rentals | 반납 후 후기/편지 흐름으로 이어진다. |
| 사진 후기 | reviewSamples | 실제 저장 대신 예시 흐름을 보여줘도 된다. |
| 감사편지 | thankYouLetters | 작성/확인 흐름 중심으로 보여준다. |

## 7. 실제로 동작해야 하는 것

아래는 유저 테스트에서 실제 상태 변화가 보여야 한다.

| 동작 | 성공 기준 |
| --- | --- |
| 포인트 차감 | 빌려오기 후 현재 포인트가 줄어든다. |
| 빌린 상태 변경 | 빌려온 옷이 빌린 상태로 표시된다. |
| 반납 상태 변경 | 반납 후 빌린 상태가 해제되거나 반납 완료 흐름으로 이동한다. |
| 화면 이동 | 핵심 플로우가 끊기지 않고 이어진다. |

## 8. 하드코딩해도 되는 것

아래는 이번 Working Prototype에서 하드코딩해도 된다.

| 항목 | 기준 |
| --- | --- |
| 자매 목록 | 이미 추가된 언니 2명 정도로 고정 |
| 옷 목록 | asset과 맞춘 샘플 옷 데이터 |
| 후기 이미지 | 미리 준비한 이미지 또는 고정 이미지 |
| 감사편지 문구 | 예시 문구 |
| 날짜 | 필요하면 고정 문구로 표시 |
| 사용자 이름 | 고정값 |

## 9. 팀 작업 기준

| 담당 | 데이터 기준 |
| --- | --- |
| John | MockData 구조, 포인트 차감, 화면 연결, 최종 흐름 통합 |
| 린 | asset 이름과 `imageName`이 맞도록 이미지 업로드 및 화면 작업 |
| 가니 | 옷장/옷 상세/빌린 상태 표시가 MockData 기준과 맞게 동작하도록 작업 |
| 로렌스 | 온보딩 후 본편 진입 기준을 맞추고 후기/편지 흐름 보조 |
| 묭 | QA 체크리스트에서 핵심 플로우와 상태 변화를 확인 |

## 10. 구현 시 주의사항

- 이번 문서는 완성형 데이터 아키텍처 문서가 아니다.
- 화면을 만들기 위해 필요한 데이터만 먼저 둔다.
- `UUID`, JSON 저장, 친구 관계, 요청/수락 모델은 필요할 때만 추가한다.
- asset 이름이 바뀌면 MockData의 `imageName`도 같이 맞춘다.
- 포인트 차감과 빌린 상태는 유저 테스트에서 반드시 확인 가능해야 한다.
- 코드 구조보다 유저 테스트 흐름 완성이 우선이다.

## 11. 완료 기준

이 데이터 기준이 반영되면 아래가 가능해야 한다.

- 팀원이 같은 MockData 기준으로 화면을 만들 수 있다.
- 린이 업로드한 asset을 옷 데이터에서 바로 사용할 수 있다.
- 가니가 옷장/상세/빌린 상태 화면을 만들 때 데이터 기준을 확인할 수 있다.
- 로렌스가 온보딩 이후 본편 진입 기준을 맞출 수 있다.
- John이 포인트 차감, 대여, 반납, 후기/편지 흐름을 연결할 수 있다.
- 묭이 유저 테스트 플로우를 기준으로 QA할 수 있다.
